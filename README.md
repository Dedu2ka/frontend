# Olo: Android-клиент

Мессенджер для Android на **Kotlin** и **Jetpack Compose**. Приложением пользуются реальные люди из закрытого круга, проект продолжает развиваться. Работает с собственным сервером на Spring WebFlux: https://github.com/Dedu2ka/olo_messenger.


## Возможности

- Регистрация и вход с проверкой данных на стороне клиента.
- Список чатов с последним сообщением и счётчиком непрочитанных, поиск пользователей.
- Диалог с временем сообщений и статусами: ожидает отправки, отправлено, доставлено, прочитано.
- **Отправка без связи**: сообщение сохраняется на устройстве и уходит автоматически, когда сеть появится.
- Push-уведомления о новых сообщениях, по нажатию открывается нужный чат.
- Профиль: отображаемое имя и аватар из галереи, выход из аккаунта с подтверждением.

## Технические решения

| Задача | Решение |
|---|---|
| Сообщение не должно потеряться или задвоиться при плохой сети | **Outbox на Room**: исходящие сообщения записываются в локальную БД и отправляются строго по порядку. Каждому присваивается `clientMessageId` (UUID), по которому сервер распознаёт повтор. Ответ 4xx снимает сообщение с очереди, сетевая ошибка оставляет его до следующей попытки |
| Безопасное хранение сессии | Токен и данные входа шифруются **AES-GCM**, ключ лежит в **Android Keystore** и не покидает защищённое хранилище устройства |
| Realtime без потери связи | WebSocket с одноразовым тикетом, **автопереподключение** с нарастающей паузой (от 1 до 30 секунд) и ping каждые 30 секунд. После переподключения данные сразу синхронизируются |
| Смена аккаунта без «утечки» данных | Все запросы живут в корутинном скоупе сессии. При выходе или смене пользователя скоуп отменяется целиком, а состояние экрана очищается, поэтому чужие данные не остаются в памяти |
| Не дублировать уведомление, когда чат уже открыт | `FirebaseMessagingService` проверяет, виден ли сейчас этот чат, и в таком случае уведомление не показывает |
| Android 13+ | Запрос разрешения `POST_NOTIFICATIONS`, канал уведомлений создаётся при запуске |
| Загрузка аватара | Изображение декодируется с уменьшением, приводится к 256×256 и сжимается в JPEG до отправки на сервер |

## Стек

- Kotlin, Jetpack Compose (Material 3), Coroutines и StateFlow
- ViewModel (`lifecycle-viewmodel-compose`)
- Retrofit 2 + Gson, OkHttp (в том числе WebSocket)
- Room (генерация кода через KSP)
- Coil для изображений
- Firebase Cloud Messaging
- Android Keystore

`minSdk 24`, `targetSdk 34`.

## Архитектура

Слоистая структура: экраны отделены от слоя данных, состояние течёт к интерфейсу через `StateFlow`.

```
com.example.olo/
├── MainActivity.kt        навигация между экранами, запуск сессии
├── data/                  сеть (Retrofit, WebSocket), репозитории,
│                          Room (очередь исходящих), хранилище сессии, push
└── ui/                    экраны Compose, ChatViewModel, тема
```

- Навигация реализована вручную: перечисление экранов и стек возврата в `MainActivity`.
- `AccountRepository` и `UserRepository` превращают HTTP-ответы в понятные интерфейсу результаты (`Authenticated`/`Rejected`, `Success`/`Failure`).
- `ChatViewModel` управляет сессией, WebSocket, списком чатов и очередью исходящих сообщений.

## Интересные места в коде

- `data/PendingMessageOutbox.kt`: очередь исходящих с порядком и идемпотентностью.
- `data/ChatWebSocketClient.kt`: тикет, подключение, переподключение с нарастающей паузой.
- `data/AuthSessionStore.kt`: шифрование сессии ключом из Android Keystore.
- `data/OloFirebaseMessagingService.kt`: показ push и подавление уведомления для открытого чата.
- `ui/ChatViewModel.kt`: жизненный цикл сессии, синхронизация, обработка событий WebSocket.

## Сборка и запуск

Нужны Android Studio и JDK 17.

1. Адрес сервера задаётся в файле `local.properties` в корне проекта (он не попадает в Git):
   ```
   olo.baseUrl=http://10.0.2.2:8080/
   ```
   `10.0.2.2` это адрес компьютера, на котором запущен эмулятор. Если строки нет, используется именно он.
2. Запусти сервер: инструкция в репозитории бэкенда.
3. Собери и запусти конфигурацию `app`.

Push-уведомления необязательны. Плагин Google Services подключается, только если есть файл `app/google-services.json`, а его создают в Firebase Console для пакета `com.example.olo`. Без него приложение собирается и работает, но push не приходит.

## Планы развития

- Замена периодической синхронизации на событийную: основной канал WebSocket, а запросы к серверу только при обрыве связи.
- Локальный кэш истории сообщений в Room для просмотра переписки без сети.
- Групповые чаты и отправка изображений.
- Внедрение зависимостей и Navigation Compose, вынесение логики в отдельный слой use case-ов.
- Хранение аватаров как файлов вместо Base64-строк в базе.
- Автотесты: валидация ввода, очередь исходящих сообщений, разбор ошибок API.
